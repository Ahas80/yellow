# rUTIs Pipeline: Script and Figure Guide

This document provides a comprehensive overview of the **Yellow RoUTIne (rUTIs)** analysis pipeline. It details the purpose, inputs, outputs, and methodology for each script, organized by analysis phase. It also serves as a reference for the key figures generated by the pipeline.

## Pipeline Overview

The pipeline is designed to analyze longitudinal clinical and genomic data from recurrent UTI (rUTI) patients. It moves from raw clinical data and WGS assemblies to complex evolutionary and genotype-phenotype association analyses.

**Core Phases:**
1.  **Phase 0: Clinical Data Foundation** - Cleaning, classification, and summary of clinical episodes.
2.  **Phase 1: WGS Assembly & Typing** - QC, typing (MLST, VF, AMR, Plasmids), and pangenome analysis.
3.  **Phase 2: Comparative Genomics** - Pairwise strain comparison, GWAS, and lineage risk analysis.
4.  **Phase 3: Longitudinal & Evolutionary Analysis** - Timeline reconstruction, within-host evolution, and variant annotation.

## Phase 0: Clinical Data Foundation

### `00_config.R`
*   **Role:** Central configuration hub.
*   **Purpose:** Defines global file paths, loads required R packages, sets color palettes, and defines helper functions used across the pipeline.
*   **Key Outputs:** None (Environment setup).

### `00a_load_clean_clinical.R`
*   **Role:** Data ingestion and standardization.
*   **Methodology:** Merges multiple clinical data batches, standardizes Participant IDs and Timepoints (T0, T1, etc.), and extracts symptom data from raw columns.
*   **Key Outputs:** `results/clinical/intermediate/clinical_merged.rds`, `assembly_metadata.csv` (initial mapping).

### `00b_classify_episodes.R`
*   **Role:** Clinical phenotype classification.
*   **Methodology:** Classifies each episode as **UTI**, **ASB**, or **Negative** based on CFU counts (>10^3/10^4) and symptom presence (Dysuria, Urgency, Fever, etc.). Assigns confidence levels to classifications.
*   **Key Outputs:** `results/clinical/status_map.csv` (The master clinical label file).

### `00c_plot_clinical_summary.R`
*   **Role:** Clinical data visualization.
*   **Methodology:** Descriptive statistics and plotting of clinical status distributions and trajectories.
*   **Key Figures:**
    *   `plots/clinical/status_distribution.png`: Bar chart of UTI/ASB/Negative counts.
    *   `plots/clinical/clinical_trajectory_sankey.png`: Flow of patients between states over time.
    *   `plots/clinical/waterfall_definitions.png`: Visualization of how case definitions filter the data.

### `00_input_snapshot.R`
*   **Role:** Debugging & Data Integrity.
*   **Methodology:** Creates snapshots (head/dimensions) of key input files (`vf_pa_all.csv`, `mlst_all.tsv`, etc.) to `results/within_person/debug/input_snapshot/` for quick verification.
*   **Key Outputs:** `results/within_person/debug/input_snapshot/dims.csv`.

### `00_make_assembly_metadata.r`
*   **Role:** Metadata Generation.
*   **Methodology:** Generates the master `assembly_metadata.csv` by linking Isolate IDs (from FASTAs or MLST) to Participant IDs and Timepoints.
*   **Key Outputs:** `assembly_metadata.csv`.

## Phase 1: WGS Assembly & Typing

### `12_wgs_exact_compare.R` (and `12a`, `12b`, `12c`)
*   **Role:** Core WGS processing pipeline.
*   **Methodology:**
    *   **QC (`12a`):** Filters assemblies based on contig count (<500), N50 (>20kb), and genome size (4.5-5.5Mb).
    *   **Core SNP (`12b`):** Uses **Parsnp** to align assemblies to a reference, call core SNPs, and build a phylogenetic tree.
    *   **Pangenome (`12c`):** Uses **Panaroo** to define core and accessory genes.
*   **Key Outputs:** `results/wgs/qc_summary.csv`, `results/wgs/core_genome.tree`, `results/wgs/snp_dists.tsv`.

### `13_visualise_panaroo_selection.R`
*   **Role:** QC Visualization.
*   **Methodology:** Visualizes which samples passed QC and were selected for Panaroo. Checks for selection bias (e.g., by infection status).
*   **Key Figures:**
    *   `plots/wgs/panaroo_selection_matrix.png`: Heatmap of QC pass/fail status per participant/timepoint.
    *   `plots/wgs/panaroo_timepoint_selection_bar.png`: Bar chart of kept vs. dropped timepoints.

### `02_gene_presence_analysis.R`
*   **Role:** Virulence Factor (VF) detection.
*   **Methodology:** Runs **Abricate** against the VFDB database. Generates presence/absence matrices.
*   **Key Outputs:** `results/vf/vf_hits_all.rds`, `results/vf/vf_pa_all.csv`.

### `04_gene_breakdown.R`
*   **Role:** Detailed gene annotation and statistical testing.
*   **Methodology:** Annotates VFs with functional categories (Adhesins, Toxins, etc.). Uses **GLMMs** (Generalized Linear Mixed Models) to test for enrichment of specific genes in UTI vs. ASB, accounting for repeated measures.
*   **Key Outputs:** `results/vf/annotated_gene_table.csv`, `results/vf/diff_focus_genes_UTI_vs_ASB_glmm.csv`.

### `05_gene_overview_plots.R`
*   **Role:** Gene prevalence visualization.
*   **Methodology:** Distinguishes "Core" VFs (>95% prevalence) from "Variable" VFs.
*   **Key Figures:**
    *   `plots/vf/gene_prevalence_bar.png`: Top 40 most common VFs.
    *   `plots/vf/variable_gene_heatmap.png`: Heatmap of variable VFs across isolates.

### `06_MLST.R` & `07_explore_MLST.R`
*   **Role:** Multi-Locus Sequence Typing.
*   **Methodology:** Assigns Sequence Types (STs) using the `mlst` tool. Analyzes ST frequency and persistence.
*   **Key Figures:** `plots/mlst/top20_STs.png` (Distribution of lineages like ST131, ST73).

### `08_core_vs_plasmid.R` & `09_inc_plasmid_network.R` & `10_replicon_heatmap.R`
*   **Role:** Plasmid analysis.
*   **Methodology:** Detects plasmid replicons (IncF, IncI, etc.) using **PlasmidFinder**. Analyzes associations between chromosomal STs and plasmid types (Fisher's exact test) and visualizes co-occurrence networks.
*   **Key Figures:**
    *   `plots/plasmids/replicon_heatmap.png`: Plasmid content across the cohort.
    *   `plots/plasmids/ST_vs_replicon_network.pdf`: Bipartite graph linking STs to Plasmids.

## Phase 2: Comparative Genomics

### `11_compare_strains.R`
*   **Role:** Pairwise isolate comparison.
*   **Methodology:** Compares every pair of isolates within a participant. Calculates:
    *   **SNP Distance** (from Parsnp/Nucmer).
    *   **Mash Distance** (MinHash).
    *   **Gene Content Jaccard Index** (VF and Plasmid).
    *   **Classification:** "Same" (≤10 SNPs), "Related" (same ST, >10 SNPs), or "Different".
*   **Key Outputs:** `results/strain_compare/pairwise_metrics.csv`.

### `11_compare_strains_MOD.R` (Extended Analysis)
*   **Role:** Extended Within-Person Strain Comparison.
*   **Methodology:** An alternative/extended version of the strain comparison script that focuses on consecutive timepoints and persistence quantification.
*   **Key Outputs:** `results/within_person/pairwise_summary.csv`, `results/within_person/persistence_by_participant.csv`.

### `14_genotype_phenotype_model.R`
*   **Role:** Bacterial GWAS (Genotype-Phenotype Association).
*   **Methodology:** Uses **GLMMs** (Mixed Models) and **GLMs** (Logistic Regression) to identify genomic features (VFs, Plasmids, STs) associated with **UTI** (vs. ASB). Adjusts for covariates.
*   **Key Outputs:** `results/gwas/gwas_multivariable_glmm.csv`.
*   **Key Figures:**
    *   `plots/gwas/volcano_plot.png`: Significance vs. Effect Size of genes.
    *   `plots/gwas/forest_plot_top_hits.png`: Odds Ratios for top markers.

### `17_lineage_analysis.R`
*   **Role:** Lineage-specific risk profiling.
*   **Methodology:** Calculates the "UTI Risk" (proportion of episodes that are UTI) for each Sequence Type.
*   **Key Figures:** `plots/lineage/st_risk_plot.png`: UTI risk probability by ST.

## Phase 3: Longitudinal & Evolutionary Analysis

### `15_longitudinal_patterns.R`
*   **Role:** Timeline reconstruction.
*   **Methodology:** Connects isolates into "Strains" based on SNP distance. Identifies **Phenotype Switch Events** (e.g., an ASB episode followed by a UTI episode caused by the *same* strain).
*   **Key Outputs:** `results/longitudinal/participant_timelines.csv`, `results/longitudinal/phenotype_switch_candidates.csv`.
*   **Key Figures:** `results/longitudinal/swimmer_plot.png`: Patient timelines showing infection status and strain persistence.

### `16_within_host_evolution.R`
*   **Role:** Micro-evolutionary analysis.
*   **Methodology:** For "Switch" pairs, calculates precise SNP distances and identifies specific gene/plasmid gains and losses.
*   **Key Outputs:** `results/longitudinal/evolution_events.csv`.

### `18_annotate_variants.R` & `20_variant_annotation_deep.R`
*   **Role:** Variant annotation.
*   **Methodology:** Parses SNP calls (from Nucmer) and maps them to genes using **Prokka GFF** files. Determines if SNPs are intergenic or within specific coding regions (CDS).
*   **Key Outputs:** `results/longitudinal/annotated_snps.csv`, `results/longitudinal/variant_annotation_detailed.csv`.

### `19_host_context.R`
*   **Role:** Host factor integration.
*   **Methodology:** Adds clinical context (Catheter use, specific symptoms) to the evolutionary switch events to check for host-driven selection.
*   **Key Outputs:** `results/longitudinal/host_context_table.csv`.

### `21_publication_figures.R`
*   **Role:** Final manuscript figures.
*   **Methodology:** Generates polished, publication-ready versions of key insights.
*   **Key Figures:**
    *   `plots/publication/Fig1_Swimmer_Plot.png`: High-quality longitudinal timelines.
    *   `plots/publication/Fig2_Mutation_Map.png`: Genomic location of mutations in switch isolates.

## Verification & Helper Scripts

### `verify_env.R`
*   **Role:** Environment Verification.
*   **Methodology:** Checks if all required R packages are installed and loadable.

### `verify_data.R`
*   **Role:** Data Integrity Check.
*   **Methodology:** Verifies the correctness of key output files (`qc_summary.csv`, `strain_pairs.csv`, etc.) by checking for expected columns, ID formats, and logical consistency.

### `RUN_COMPLETE_ANALYSIS.sh`
*   **Role:** Master Execution Script.
*   **Methodology:** Orchestrates the entire pipeline execution order, from config to publication figures.

### `11_cleanup.sh` & `13_deep_clean.sh`
*   **Role:** Disk Space Management.
*   **Methodology:** Removes intermediate files (like temp FASTAs or uncompressed outputs) to save space.
